# 전시 설치·운영 가이드 (초보자용)

이 문서는 **코드를 처음 보는 사람도** AFTERLIGHT를 아이패드 + 맥북 +
아두이노 + 프로젝터(TouchDesigner) 구성으로 띄우고, 손 감지 센서로
별을 보내는 전체 흐름을 한 단계씩 확인할 수 있도록 쓴 것이다.

코드가 "왜 이렇게 생겼는지"는 [`README.md`](../README.md)와
[`server/README.md`](../server/README.md)에 있다. 이 문서는 "지금 뭘
눌러야 하는지"만 다룬다.

---

## 0. 장비와 네트워크

```
┌────────────┐   같은 Wi-Fi    ┌──────────────────────────┐
│   iPad     │ ◀──────────────▶ │       MacBook            │
│  (Safari)  │   WebSocket      │  server/index.js (다리)  │
└────────────┘                  │  Arduino Uno (USB)       │
                                 │  TouchDesigner           │
                                 └─────────────┬────────────┘
                                               │ HDMI
                                        ┌──────▼──────┐
                                        │  프로젝터    │
                                        └─────────────┘
       Arduino Uno ──USB(시리얼)── MacBook
       HC-SR04 + LED 5개 ── Arduino Uno의 핀
```

**필요한 것**

- MacBook: Node.js 20 이상, Arduino IDE, TouchDesigner
- iPad: Safari, MacBook과 **같은 Wi-Fi**
- Arduino Uno + USB 케이블 + HC-SR04 + LED 5개 + 저항 + 브레드보드/점퍼선
- (선택) 영수증 프린터 — 없어도 전부 돌아간다

**핀 배선** (아두이노를 실제로 연결할 때, [6단계](#6-arduino-시리얼-연동)에서 쓴다)

| 부품 | 핀 |
| --- | --- |
| HC-SR04 VCC | 5V |
| HC-SR04 GND | GND |
| HC-SR04 TRIG | 9 |
| HC-SR04 ECHO | 10 |
| LED 5개 (저항 거쳐 GND로) | 2 · 3 · 4 · 5 · 6 |

## 1. 기존 기능 분석 (이미 끝남 — 결과만 확인)

이 프로젝트는 이미 React + Vite + TypeScript로 짜여 있고, 기록·감정·
간직/흘려보냄·별자리·도감·우주·소리·영수증이 전부 동작한다. 저장은
브라우저의 `localStorage`(실제 통 `afterlight.universe.v1` / 점검 통
`afterlight.universe.test.v1`, 둘을 섞지 않음)에 한다. TouchDesigner·
아두이노·영수증 프린터와 잇는 WebSocket 다리(`server/`)도 이미 있었고,
이번에 손 감지 센서·LED 사이드채널만 더했다.

**확인 방법**

```bash
npm run check        # 349곳 넘는 순수 로직 검증 (브라우저 없이)
npm run bridge:test  # 다리를 처음부터 끝까지 (83곳)
npm run typecheck    # 타입 오류 없는지
```

전부 `0곳 실패`로 끝나야 한다. 하나라도 실패하면 이후 단계로 넘어가지
않는다 — 기반이 깨진 상태로 장비를 연결하면 어디가 문제인지 더 알기
어려워진다.

## 2. MacBook 로컬 연결 서버

MacBook이 iPad · 아두이노 · TouchDesigner를 모두 USB/Wi-Fi로 붙잡고
있는 **중앙 서버**다. 서버 자체는 아무것도 저장하지 않는다 — 지나가는
신호를 한 번 보고 흘려보낼 뿐이다.

### 2-1. 설정 파일 만들기 (MacBook IP를 코드에 적지 않는다)

```bash
cp server/config.example.json server/config.local.json
```

`server/config.local.json`을 열어 `host`를 비워 두고 `lan: true`로
바꾼다. (`config.local.json`은 전시장마다 다르므로 저장소에 올라가지
않는다 — `.gitignore`에 이미 등록되어 있다.)

```json
{
  "lan": true,
  "port": 9981,
  "printer": "file"
}
```

### 2-2. 서버 띄우기

```bash
npm run bridge:lan
```

터미널에 이런 줄이 뜬다.

```
설정 파일 .../server/config.local.json
하늘(브라우저)   ws://192.168.0.7:9981/sky
벽(TouchDesigner) ws://192.168.0.7:9981/td
```

**이 `192.168.0.7`이 지금 MacBook의 실제 주소다.** 공유기가 바뀌거나
다음 날 다시 켜면 숫자가 달라질 수 있다 — 그래서 코드에 적지 않고,
**이 창에 뜨는 값을 그때그때 읷는다.**

### 확인 방법

- 터미널에 `아두이노 쓰지 않음`, `프린터 file:receipts.txt` 같은 줄이
  보이면 서버가 켜진 것이다.
- `Ctrl+C`로 꺼도 다른 화면(기록·우주 등)에는 아무 영향이 없어야 한다
  — "다리가 없어도 작품은 그대로 돈다"가 이 프로젝트의 원칙이다.

## 3. iPad 웹사이트 실시간 연결

### 3-1. MacBook에서 웹사이트도 같은 Wi-Fi로 열어 둔다

새 터미널 창(서버는 그대로 켜 둔 채로):

```bash
npm run dev
```

터미널에 `Network: http://192.168.0.7:5173/` 같은 줄이 뜬다. **2-2에서
본 주소와 같은 숫자**여야 한다(같은 기계니까 같다).

### 3-2. iPad Safari에서 그 주소를 연다

```
http://192.168.0.7:5173/
```

### 확인 방법

- 대기 화면(별이 떠 있는 화면)이 보이면 연결된 것이다.
- 화면 아래(개발 중에는 왼쪽 아래 `연결 상태 판`)에 "하늘 ↔ 다리 ·
  붙음"이 보이면 iPad와 MacBook 서버가 실시간으로 이어진 것이다.
- **서버를 끄고 다시 켜 봐도** 몇 초 안에 "붙음"으로 저절로 돌아와야
  한다(0.9 → 1.8 → 3.6 → 8 → 30초 간격으로 스스로 다시 붙는다). 사람이
  iPad를 새로고침할 필요가 없다.

> Safari에서 iPad를 **전체화면 키오스크**로 쓰려면, 설정 앱 →
> 손쉬운 사용 → 안내된 접근 모드를 켜고 Safari를 그 모드로 띄운다.
> (이 프로젝트의 자체 전체화면 요청은 첫 터치에서 걸리지만, iOS
> Safari는 막는 경우가 있다 — 그래도 화면은 그대로 작동한다.)

## 4. 센서 상태 시뮬레이션 (아두이노 없이)

아두이노가 아직 없어도, 센서 흐름을 처음부터 끝까지 확인할 수 있다.

### 방법 A — 개발자 패널 (가장 쉽다)

`npm run dev`로 띄우면(또는 주소에 `?test=1`을 붙이면) 화면 **왼쪽 위에
"센서 시뮬레이션"** 패널이 뜬다. "누르고 있기" 버튼을 1초 이상 꾹
누르면 — 실제로 손을 가까이 댄 것과 똑같이 — 별이 전송된다.

### 방법 B — 터미널 대역 (서버까지 포함해 시험할 때)

```bash
npm run bridge:sim   # 창 1 — 다리
npm run sensor        # 창 2 — h 가까이 · l 멀리
npm run dev            # 창 3 — 하늘
```

`npm run sensor` 창에서 `h`를 1초 넘게 누르고 있으면 전송된다.

### 확인 방법

- `record` → `emotion` → `choice` 화면을 거쳐 **`confirm` 화면에
  있을 때만** 센서 입력이 전송으로 이어져야 한다. 다른 화면에서
  `h`를 눌러도 아무 일도 없어야 한다.
- 1초를 못 채우고 떼면(`l`을 빨리 누르면) 전송되지 않아야 한다.
- 전송 뒤에는 `l`(손을 뗀 것)을 눌렀다가 다시 `h`를 눌러야 **다음**
  전송이 된다 — 같은 손짓으로 두 번 보내지지 않는다.

## 5. 전송 화면 UI

버튼이 사라지고, 화면 상태가 다음처럼 바뀐다 (`src/components/SensorGate.tsx`,
문구는 `src/constants/text.exhibit.ts`의 `SENSOR`).

| 상태 | 화면 문구 | 언제 |
| --- | --- | --- |
| READY | "센서 위에 손을 가까이 가져가 주세요." | 손이 멀 때 — 기본 상태 |
| NEAR | "당신의 빛이 깨어나고 있어요." | 가까워져 보유하는 동안. 화면 중앙의 작은 빛이 보유 진행률만큼 부드럽게 밝아진다 |
| SENDING | "당신의 시간이 우주로 향하고 있어요." | 1초 보유를 채운 뒤, LED 다섯이 순서대로 켜지는 동안 |
| ARRIVED | "당신의 별이 우주에 도착했어요." | LED 다섯이 다 켜지고 TouchDesigner의 확인까지 받은 뒤 |
| ERROR | "센서와의 연결이 끊어졌습니다." | 거리 신호가 1.5초 넘게 오지 않을 때 |

**개발 중에만** 보이는 보조 버튼(옛 "시간을 보내기")이 남아 있다 —
`isTestMode()`로 가려서 전시 빌드에는 나오지 않는다.

### 확인 방법

```bash
npm run build && npm run preview
```

주소에 `?test=1`을 **붙이지 않고** 열어 `confirm` 화면까지 가 보면
보조 버튼이 보이지 않아야 한다(전시 빌드와 같은 모양). `?test=1`을
붙이면 다시 보인다.

## 6. Arduino 시리얼 연동

### 6-1. 배선

위 [0장의 표](#0-장비와-네트워크)대로 HC-SR04와 LED 5개를 연결한다.

### 6-2. 펌웨어 올리기

1. Arduino IDE를 열고 `server/firmware/afterlight_sensor/afterlight_sensor.ino`를 연다.
2. 보드: **Arduino Uno**, 포트: MacBook에 연결했을 때 새로 생긴 `/dev/tty.usbmodemXXXX` 선택.
3. 업로드.
4. Arduino IDE의 **시리얼 모니터**(115200bps)를 열면 1초에 10번쯤
   `{"sensor":"distance","cm":...}` 줄이 올라오는 게 보여야 한다. 손을
   가까이 대면 `cm` 값이 작아진다.

### 6-3. 서버에 패키지를 더한다 (아두이노를 실제로 쓸 때만)

```bash
npm i serialport
```

### 6-4. 서버를 아두이노와 함께 띄운다

`server/config.local.json`에 포트를 적어 둔다(시리얼 모니터는 반드시
꺼 둔다 — 포트를 양쪽에서 동시에 열 수 없다).

```json
{
  "lan": true,
  "arduino": "/dev/tty.usbmodem1101",
  "baud": 115200
}
```

```bash
npm run bridge:lan
```

### 확인 방법

- 터미널에 `아두이노: open /dev/tty.usbmodem1101 @ 115200`이 보이면
  연결된 것이다.
- iPad의 `confirm` 화면에서 **실제로 손을 HC-SR04 위에 가져가면**
  화면의 작은 빛이 밝아지고, 1초 뒤 전송이 시작돼야 한다.
- 케이블을 뽑아 보면 화면에 "센서와의 연결이 끊어졌습니다"가 뜨고,
  다시 꽂으면 되돌아와야 한다.

## 7. LED 5개 연출 연동

LED는 **하늘(iPad의 웹사이트)이 기준 시계를 쥔다** — `SceneSending`이
전송 진행을 다섯 단계로 나눠(2.6초 ÷ 5) 매 단계 `led.set` 신호를
서버로 보내고, 서버가 그걸 그대로 시리얼로 적어 보낸다. 아두이노는
"몇 개를 켜라"는 명령을 받아 그대로 켜는 단순 실행기다.

화면의 진행 점 다섯 개와 LED 다섯 개가 **같은 순간에** 늘어나야
한다 — 둘 다 같은 웹사이트 타이머를 보고 있기 때문이다.

### 확인 방법

- [6단계](#6-arduino-시리얼-연동)처럼 아두이노를 연결한 상태에서 전송해 본다.
- iPad 화면의 진행 점이 하나 켜질 때, **거의 동시에** 실제 LED도 하나
  켜져야 한다(눈에 보이는 지연은 네트워크 한 틱 정도, 1초 미만이어야 한다).
- 아두이노 없이도(4단계의 시뮬레이션) 화면의 진행 점 다섯 개는 그대로
  움직여야 한다 — LED가 없어도 화면 연출은 멈추지 않는다.

## 8. TouchDesigner 별 생성 연동

TouchDesigner 쪽은 **기존 프로젝트를 그대로 둔다.** WebSocket DAT 하나만
더하면 된다. 자세한 프로토콜은 [`server/README.md`](../server/README.md)의
"TouchDesigner 쪽"에 있다. 요약:

### 8-1. WebSocket DAT 설정

| 칸 | 값 |
| --- | --- |
| Network Address | 2단계에서 본 MacBook의 IP (예: `192.168.0.7`) |
| Network Port | `9981` |
| Request Url | `/td` |
| Active | On |

### 8-2. 받는 쪽 스크립트 (요지)

`star.requested`가 오면 `star['transferId']`(이 전송 한 건을 가리키는
고유 이름 — 지금은 `star['id']`와 같은 값)로 별 하나를 그린다. **문장
원문은 애초에 오지 않는다** — 감정·간직/흘려보냄·자리·색에 필요한
정보(`emotion`, `type`, `x`, `y`, `brightness`, `seed`, `constellation`)
만 온다.

실제로 화면에 별을 띄운 뒤에는 **반드시** 이렇게 돌려준다.

```python
op('bridge').sendText(json.dumps({'command': 'shown', 'starId': star['transferId']}))
```

이 응답이 와야 iPad 화면이 "도착했어요"로 넘어간다(LED 연출이 다 끝난
뒤에도, **이 응답이 없으면 넉넉히 6초 기다렸다가** 그냥 넘어간다 —
TouchDesigner가 없어도 체험이 멈추지 않는다).

### 확인 방법 (TouchDesigner 없이 먼저)

```bash
npm run bridge:sim
npm run wall --slow   # 받고 0.4초 뒤에 '띄웠다'고 알리는 대역
npm run dev
```

4단계의 시뮬레이션으로 전송해 보면, "SENDING" 화면이 LED 다섯 단계가
끝난 **뒤에도** 0.4초 더 머물다가 "ARRIVED"로 넘어가야 한다 — 벽의
확인을 기다린다는 뜻이다. `npm run wall`(대역을 끈 채로, 즉 벽이 없는
상태)로 시험하면 6초 뒤에 그냥 "ARRIVED"로 넘어가야 한다.

### 확인 방법 (진짜 TouchDesigner로)

- TD 네트워크 패널에서 연결이 뜨는지 본다.
- iPad에서 전송하면 TD 쪽에 별 데이터가 들어오는지 본다(표에
  `appendRow`로 쌓이게 해 두면 보기 쉽다).
- 실제로 화면(프로젝터)에 별이 뜨는 걸 확인한 뒤 `shown`을 보내고,
  iPad가 그 순간 "ARRIVED"로 넘어가는지 본다.

## 9. 전체 통합 테스트

### 9-1. 자동 검증 (사람이 보지 않아도 되는 것)

```bash
npm run typecheck
npm run check
npm run bridge:test
npm run build
```

넷 다 오류 없이 끝나야 한다.

### 9-2. 장비를 다 꽂고 한 번 처음부터

1. MacBook: `server/config.local.json`에 `lan:true`, `arduino` 경로를 적는다.
2. `npm run bridge:lan` (서버) — 아두이노 연결 로그 확인.
3. TouchDesigner 프로젝트를 열고 WebSocket DAT을 켠다.
4. `npm run dev`로 iPad가 열 주소를 확보한다.
5. iPad Safari로 그 주소를 연다.
6. 관객처럼 처음부터: 터치 → 기록 → 감정 → 간직/흘려보냄 →
   **`confirm` 화면에서 HC-SR04에 손을 가까이 1초** → LED 다섯이
   순서대로 켜짐 → 프로젝터 화면에 별이 뜸 → iPad가 "ARRIVED" →
   도착 화면.
7. Wi-Fi를 잠깐 끄고 켜 본다 — iPad가 스스로 다시 붙는지, 그동안
   화면이 멈추지 않는지 본다.
8. 아두이노 USB를 잠깐 뽑아 본다 — "센서와의 연결이 끊어졌습니다"가
   뜨고, [운영자용 수동 전송](#9-3-운영자용-수동-전송)으로 대신 보낼
   수 있는지 본다.
9. 관객 하나를 끝낸 뒤 "또 하나 보내기"로 처음 화면까지 돌아가, **그
   사람이 적은 글이 다음 화면에 남아 있지 않은지** 본다.

### 9-3. 운영자용 수동 전송

센서가 먼지·각도·배터리 등으로 오작동할 때, `confirm` 화면
**오른쪽 위 구석을 1.5초 길게 누르면** 센서 없이도 그대로 보낸다
(`src/components/OperatorOverride.tsx`). 화면에는 아무 표시도 없다 —
운영자만 이 문서를 보고 알고 있으면 된다.

### 9-4. 다음 관객을 위한 초기화

- 45초(도착 화면은 20초) 동안 아무도 손대지 않으면 저절로 대기 화면으로
  돌아가고, **적던 글만** 지워진다. 보낸 별은 지워지지 않는다.
- 도착 화면의 "처음으로"를 눌러도 즉시 같은 일이 일어난다.

### 9-5. 전시 중 자주 쓰는 명령 모음

```bash
npm run bridge:lan     # 서버 (아두이노 꽂혀 있으면 자동으로 같이 켜진다)
npm run dev             # 웹사이트 (여러 iPad를 같은 서버에 붙일 때도 이거 하나)
npm run build           # 전시용으로 굽기
npm run preview          # 구운 결과를 그대로 확인
```

장비가 하나도 없어도(서버도 안 띄워도) `npm run dev`만으로 기록·감정·
간직/흘려보냄·우주·소리는 전부 그대로 동작한다 — 이 프로젝트의
원칙이 "다리가 없어도 작품은 돈다"이기 때문이다. 다만 그때는 센서로
보낼 길이 없으므로, 개발자 전용 보조 버튼(`?test=1`)이나 4단계의
시뮬레이션으로 대신한다.
